# Persona roadmap — Group 12: Franchise operator (601-650)

Branch `feat/persona-group4-rest`, PR #809. Surveyed 2026-11-23 at `018fa3ccf`. Read-only survey; nothing built, nothing changed.

Status: EXISTS = shipped before this batch (evidence given); PARTIAL = usable in part, needs extension; BUILD = not present in usable form. `verified` marks evidence checked firsthand in this survey.

Franchise domain as found: the OxSteed territory-franchise pipeline in `server/routes/franchise.js` (`POST /applications`, `GET /my-applications`, `GET /territory-stats`, `GET /territory-helpers`, admin list/get/patch, notes, checklist items, agreement upsert/sign, fee collection, activate-store), `server/controllers/franchiseController.js` (1473 lines: 9-status pipeline, 8-item seeded intake checklist, agreement with fee/royalty terms, fail-closed activation, per-territory grant sync), `server/controllers/franchiseTerritoryController.js` (territory KPIs + helper roster, city/region string matching), `server/services/franchiseRoyaltyService.js` (royalty + marketing-fee accrual as ledger bookkeeping, "No money moves here"), `server/services/restaurantFranchiseLocationAgreementService.js` (explicit store-to-agreement mapping), client `FranchiseIntakePage.jsx`, `FranchiseApplicantDashboard.jsx`, `FranchiseTerritoryOpsPage.jsx`, admin `client/src/admin/pages/super/FranchiseHQPage.jsx` (743 lines), capability `franchise.operate` (`server/services/access/policyRegistry.js:253-272`, version `franchise-policy-1`, per-territory grant, `applicantMayRequest` false, activation requires `territory_assignment`), signup intent `franchise` (`client/src/utils/signupPersonas.js:17`, `server/services/access/signupIntent.js:39`, status path `/franchise/apply`).

Two franchise domains exist and must not be confused: (a) the OxSteed territory franchise above (the operator persona's own pipeline); (b) the restaurant-brand franchise in `server/routes/restaurantBrands.js` (`/:brandId/franchise-report`, `/:brandId/franchise-mappings`) and `client/src/pages/food/BrandHQPanel.jsx` (brand compliance, store comparison, royalty report, menu publish/rollouts), plus the restaurant training/audit system in `server/routes/restaurants.js:347-399`. Many PARTIAL rows below rest on reusing (b) or the generic business/support systems; the build must decide whether the operator surface is territory-scoped or reuses those restaurant/business surfaces.

Money note: unlike Group 11 (D-257: rental money off-platform, record-only), franchise money has NO decision yet. The machinery exists server-side — initial-fee collection is recorded, never moved (`recordFranchiseFeeCollection`, `franchiseController.js:1184`); royalties accrue as `platform_ledger` bookkeeping (`franchiseRoyaltyService.js:33`, "No money moves here"); activation fails closed until the fee is collected or waived (`franchiseController.js:1184-1258`, `activateFranchiseStore`). No item 601-650 is itself a money-moving action; the fee/royalty model decision is still open (see Next step).
