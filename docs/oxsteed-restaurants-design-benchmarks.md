# OxSteed Restaurants Design Benchmarks

Updated: 2026-06-18

Purpose: keep the 8 OxSteed Restaurants iOS apps aligned to production-grade patterns seen in major restaurant and restaurant-tech products while preserving OxSteed's independent-brand positioning.

## What the best apps consistently do

1. McDonald's and Starbucks push immediate customer value first.
   Order-ahead, rewards, deals, and visit planning are all surfaced early instead of hidden behind account management or utility chrome.

2. Toast and Square frame operator tools around task completion, not feature browsing.
   POS, kitchen, kiosk, and manager flows are sold as fast execution systems for real service moments: take order, send ticket, manage queue, close issue.

3. Big-brand back-of-house tools reduce ambiguity.
   Kitchen and counter surfaces make status, urgency, and next action visually obvious because staff use them under time pressure.

4. Good in-store guest surfaces are readable from distance and usable in seconds.
   Kiosk and pickup boards need large hierarchy, strong status contrast, and as few decisions as possible per step.

5. The strongest franchise systems make consistency visible.
   Training, SOP, checklist, and badge systems are part of the product, not hidden admin pages.

## What that means for OxSteed Restaurants

- Customer: discovery and reorder momentum must stay visible, but the restaurant should still feel like its own brand inside the OxSteed network.
- Manager: the first screen should answer "what needs attention now?" before showing deep controls.
- POS: the first screen should minimize taps and decision friction during a line rush.
- Kitchen: the first screen should separate new, preparing, ready, and delayed work with obvious progression.
- Kiosk: the first screen should reassure guests that self-ordering is easy and that queue/pickup visibility is trustworthy.
- Crew: the first screen should connect training progress to live shift readiness.
- Inventory: the first screen should raise low-stock and waste risk before it becomes a service problem.
- Runner: the first screen should make the next stop, proof rule, and exception path obvious.

## Applied in the 2026-06-18 shell pass

- Shared workspace hero now reinforces "independent brand, shared network" instead of a generic multi-app shell.
- Role apps now open with task-priority cards and operational stats instead of only generic section headers.
- Mode switching in Manager, POS, Kiosk, Crew, Inventory, and Runner now uses richer action cards with titles, icons, and purpose copy.
- The shared design system now includes reusable priority, brand-message, mode-card, and operational-stat components so future screens can stay consistent.
